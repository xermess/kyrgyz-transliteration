Транслитерация кыргызского языка на Python: кириллица ⇄ латиница, четыре схемы,
восстановление регистра, восстановление ө/ү/ң по словарю, слаги для URL и
консольная утилита. Без зависимостей, Python 3.9+.

```python
from kyrgyz_transliteration import to_latin, to_cyrillic, slugify

to_latin("Кыргыз Республикасы")             # 'Kırgız Respublikası'
to_latin("Кыргыз Республикасы", "bgn")      # 'Kyrgyz Respublikasy'
to_cyrillic("Kyrgyz Respublikasy", "bgn")   # 'Кыргыз Республикасы'
to_cyrillic("dongolok", wordlist=True)      # 'дөңгөлөк' — латиница без диакритики
slugify("Ысык-Көл облусу")                  # 'ysyk-kol-oblusu'
```

## Схемы

| Схема | Назначение | Обратимость |
|---|---|---|
| `turkic` (по умолчанию) | кыргызская латиница на базе общетюркского алфавита: `ж → c`, `ч → ç`, `ң → ñ`, `ы → ı` | почти полная: `е`/`э`, `ъ`, `ь` не различаются |
| `bgn` | BGN/PCGN — то, что используют карты, паспорта и англоязычная пресса | с потерями: `й`/`ы` → `y`, `е`/`э` → `e` |
| `iso9` | ISO 9:1995 / ГОСТ 7.79-2000 система А — научная транслитерация | полная, посимвольная |
| `ascii` | латиница без диакритики для URL, логинов, легаси-систем | с потерями: `о`/`ө`, `у`/`ү`, `е`/`э`, `й`/`ы` |

```python
from kyrgyz_transliteration import list_schemes

for scheme in list_schemes():
    print(scheme.name, "-", scheme.title, "(с потерями)" if scheme.lossy else "")
```

### Какую схему выбрать

- **`iso9`** — если текст должен вернуться из латиницы байт в байт (архивы,
  библиотечные описания, обмен данными).
- **`turkic`** — если нужна читаемая кыргызская латиница: буквы те же, что в
  общетюркском алфавите (`ж → c`, `ч → ç`), так что запись близка и к кыргызской
  латинице 1928–1940 годов, и к современным проектам перехода на латиницу.
- **`bgn`** — если результат увидят англоязычные читатели: так пишут топонимы на
  картах, в паспортах и в прессе.
- **`ascii`** — если латиница нужна технике: URL, логины, имена файлов, системы
  без поддержки Unicode. Для URL есть готовый [`slugify`](#api).

Один и тот же текст в четырёх схемах:

| Кириллица | turkic | bgn | iso9 | ascii |
|---|---|---|---|---|
| Ысык-Көл | `Isık-Köl` | `Ysyk-Köl` | `Ysyk-Kôl` | `Ysyk-Kol` |
| жаңылык | `cañılık` | `jangylyk` | `žaņylyk` | `jangylyk` |
| мүмкүнчүлүк | `mümkünçülük` | `mümkünchülük` | `mùmkùnčùlùk` | `mumkunchuluk` |
| Чүй облусу | `Çüy oblusu` | `Chüy oblusu` | `Čùj oblusu` | `Chuy oblusu` |
| айтса | `aytsa` | `aytsa` | `ajtsa` | `aytsa` |

## API

### `to_latin(text, scheme="turkic")`

Кириллица → латиница. Регистр сохраняется, включая многобуквенные замены и
аббревиатуры: `Ёлка → Yolka`, `ЁЛКА → YOLKA`. Всё, что не буква (цифры,
пунктуация, разметка, переводы строк), проходит насквозь.

```python
to_latin("Ош шаары", "bgn")        # 'Osh shaary'
to_latin("КЫРГЫЗ ЭЛИ")             # 'KIRGIZ ELİ'
to_latin("Бишкек, 2026-жыл")       # 'Bişkek, 2026-cıl'
```

В схеме `turkic` латинская `i` пишется по-турецки: заглавная — `İ`, а заглавная
`I` читается обратно как `ы`.

### `to_cyrillic(text, scheme="turkic", wordlist=None)`

Латиница → кириллица. Диграфы имеют приоритет над отдельными буквами
(`shch → щ`, `yo → ё`), а неоднозначные буквы разбираются по контексту:

```python
to_cyrillic("Ysyk-Köl", "bgn")     # 'Ысык-Көл'  (y после согласной — ы)
to_cyrillic("oy-toy", "bgn")       # 'ой-той'    (y между гласной и согласной — й)
to_cyrillic("bijik", "iso9")       # 'бийик'
to_cyrillic("aytsa", "bgn")        # 'айтса'     (ts после гласной — т + с)
to_cyrillic("kontsert", "bgn")     # 'концерт'   (в остальных случаях — ц)
to_cyrillic("emgek")               # 'эмгек'     (e в начале слова — э)
```

Если латиница набрана без диакритики (`dongolok` вместо `döñgölök`), передайте
словарь — см. [раздел ниже](#латиница-без-диакритики).

### `transliterate(text, scheme="turkic", direction="auto", wordlist=None)`

Направление по преобладающей письменности: `"auto"`, `"latin"` или `"cyrillic"`.

```python
transliterate("Бишкек")            # 'Bişkek'
transliterate("Bişkek")            # 'Бишкек'
```

### `slugify(text, separator="-", scheme="ascii")`

ASCII-слаг для URL, имён файлов и идентификаторов: только `a-z`, `0-9` и
разделитель.

```python
slugify("Ысык-Көл облусу")             # 'ysyk-kol-oblusu'
slugify("Жалал-Абад", separator="_")   # 'jalal_abad'
```

### `detect_script(text)`

`"cyrillic"`, `"latin"`, `"mixed"` или `"unknown"`.

### Прочее

- `alphabet_table(scheme)` — список пар `(кириллица, латиница)` для всех 36 букв.
- `Wordlist`, `builtin_wordlist()`, `restore_words()`, `ascii_key()` — словарь для
  латиницы без диакритики.
- `get_scheme(name)`, `list_schemes()`, `SCHEMES` — доступ к схемам;
  `UnknownSchemeError` — неизвестное имя.
- `Scheme`, `Table`, `apply_table`, `match_case` — собственные схемы и движок.
- `CYRILLIC_LETTERS` — кыргызский алфавит строкой.

## Латиница без диакритики

`turkic` и `bgn` обратимы, только если латиница написана полностью. Но пишут
обычно проще — `dongolok`, `tushunuk`, `kocho`, — а по такой записи выбрать между
«дөңгөлөк» и «донголок» нельзя: оба слова подчиняются гармонии гласных. Поэтому
восстановление работает по словарю.

```python
from kyrgyz_transliteration import to_cyrillic

to_cyrillic("dongolok")                  # 'донголок' — буквальный разбор
to_cyrillic("dongolok", wordlist=True)   # 'дөңгөлөк' — по встроенному словарю
to_cyrillic("Kocho jok", wordlist=True)  # 'Көчө жок'
```

`wordlist=True` берёт встроенный список частотных кыргызских слов (~280 слов).
Как это работает:

1. слово ищется в словаре по «сплющенному» ASCII-ключу — учитываются все
   варианты набора: `ө`/`ү` как `o`/`u`, `ң` как `n` или `ng`, `ж` как `j`, `zh`
   или `c`, `ы` как `y` или `i`;
2. если точного совпадения нет — ищется самая длинная основа из словаря
   (минимум 4 символа), а к суффиксу применяется гармония гласных:
   `dongolokton → дөңгөлөктөн`, `okmottun → өкмөттүн`;
3. если слово не нашлось или на ключ претендуют два слова (`kol` — это и «кол»,
   и «көл»), оно разбирается обычными правилами схемы. То есть словарь ничего не
   портит: без него было бы то же самое.

Свой список слов (одно слово в строке, кириллицей, `#` — комментарий):

```python
from kyrgyz_transliteration import Wordlist, builtin_wordlist, to_cyrillic

words = Wordlist.from_file("kyrgyz.txt")                      # только свои слова
words = Wordlist(builtin_wordlist().words()).add(["көпөлөк"])  # встроенные + свои

to_cyrillic("kopolokton", wordlist=words)   # 'көпөлөктөн'
words.ambiguous_keys()                      # ключи, которые словарь не решает
```

Чем полнее список, тем лучше результат: встроенный набор — это стартовая точка,
а не полный словарь кыргызского языка.

Справочник `Wordlist`:

| Что | Зачем |
|---|---|
| `Wordlist(words, min_stem=4)` | собрать словарь из слов (кириллицей); `min_stem` — минимальная длина основы при поиске по началу слова |
| `Wordlist.from_file(path)` | прочитать список из файла: одно слово в строке, `#` — комментарий |
| `.add(words)` | дописать слова; возвращает сам словарь, так что вызовы можно цеплять |
| `.lookup(typed)` | слово по набранной латинице или `None`, если его нет либо ключ неоднозначен |
| `.lookup_stem(key)` | `(слово, длина ключа основы)` — самая длинная однозначная основа |
| `.ambiguous_keys()` | ключи, на которые претендует больше одного слова |
| `.words()`, `len(...)`, `"dongolok" in ...` | содержимое словаря |
| `builtin_wordlist()` | встроенный список (кешируется, не меняйте его на месте — делайте копию через `Wordlist(builtin_wordlist().words())`) |
| `restore_words(text, wordlist)` | только восстановление слов, без транслитерации: латинские слова из словаря заменяются кириллическими |
| `ascii_key(word)` | ключ слова: нижний регистр без диакритики (`döñgölök` → `donggolok`) |

## Свои схемы

Схема — это таблица «кириллица → латиница» плюс необязательные уточнения.
Обратная таблица строится автоматически.

```python
from kyrgyz_transliteration import SCHEMES, Scheme, register_scheme, to_latin

register_scheme(
    Scheme(
        name="passport",
        title="Как в моих документах",
        mapping=dict(SCHEMES["ascii"].mapping, ж="zh", ө="oe", ү="ue", ю="iu", я="ia"),
        reverse_word_initial={"e": "э"},
    )
)

to_latin("Жаңыл", "passport")   # 'Zhangyl'
```

Полезные поля `Scheme`:

- `word_initial` — замены только в начале слова;
- `reverse_mapping`, `reverse_word_initial` — правки обратной таблицы;
- `latin_upper` / `latin_lower` — регистровые исключения латиницы (`i ⇄ İ`);
- `forward_contextual` / `reverse_contextual` — контекстные правила
  `(регулярка, маркер)`; правило помечает неоднозначный символ маркером, а
  маркер переводится через `reverse_mapping`. Замена обязана быть той же длины,
  что и совпадение, поэтому контекст задаётся через `(?<=...)` и `(?=...)`.

## Командная строка

```bash
$ kyrgyz-translit "Кыргыз Республикасы"
Kırgız Respublikası

$ kyrgyz-translit -s bgn "Ысык-Көл"
Ysyk-Köl

$ kyrgyz-translit -d cyrillic -s bgn "Ysyk-Köl"
Ысык-Көл

$ kyrgyz-translit --slug "Жалал-Абад облусу"
jalal-abad-oblusu

$ cat text.txt | kyrgyz-translit -s iso9 > text-latin.txt

$ kyrgyz-translit -w "dongolok kocho jok"
дөңгөлөк көчө жок

$ kyrgyz-translit --wordlist kyrgyz.txt "koygoydon"
көйгөйдөн

$ kyrgyz-translit --list          # схемы с описаниями
$ kyrgyz-translit --table bgn     # таблица соответствий
$ kyrgyz-translit --detect "Bişkek"
latin
```

То же самое доступно как `python -m kyrgyz_transliteration`.

## Как это работает

Один проход по тексту, никаких зависимостей и никакой магии.

1. **Подготовка таблицы.** Схема хранит таблицу «кириллица → латиница»; обратная
   таблица строится из неё автоматически при первом обращении и кешируется.
   Пустые замены (`ъ`, `ь`) в обратную таблицу не попадают, а при конфликте
   побеждает буква, объявленная раньше.
2. **Контекстные правила.** До основного прохода по тексту проходят регулярки,
   которые помечают неоднозначные символы служебными маркерами: `y` между
   гласной и согласной → маркер «й», `t` перед `s` после гласной → маркер «т».
   Маркер обязан быть той же длины, что и совпадение, — иначе движок поднимает
   `ValueError`, — поэтому контекст задаётся только через `(?<=...)` и `(?=...)`,
   а нумерация символов остаётся прежней.
3. **Жадное сопоставление.** Для каждой позиции берётся самая длинная
   подходящая последовательность (`shch` раньше `sh`, `sh` раньше `s`), в начале
   слова сначала проверяется таблица `word_initial`. Что не нашлось — цифры,
   пунктуация, разметка, чужие алфавиты — копируется как есть.
4. **Регистр.** Он берётся из исходного фрагмента, а не из замены: слово целиком
   в верхнем регистре даёт `ЁЛКА → YOLKA`, а с заглавной — `Ёлка → Yolka`.
   Регистровые исключения латиницы (`i ⇄ İ` в `turkic`) задаёт сама схема.
5. **Словарь** (если передан) работает до шага 2 и только в направлении «латиница
   → кириллица»: найденные слова сразу заменяются кириллическими, остальное
   достаётся правилам.

Точки расширения — `Scheme` (своя схема), `Table` + `apply_table` (свой движок
на готовой таблице), `match_case` (восстановление регистра отдельно).

## Рецепты

**Слаг для URL.**

```python
from kyrgyz_transliteration import slugify

slugify("Ысык-Көл облусунун жаңылыктары")   # 'ysyk-kol-oblusunun-jangylyktary'
```

**Поиск, которому всё равно, чем набран запрос.** Приводим запрос к кириллице и
ищем по одному индексу:

```python
from kyrgyz_transliteration import detect_script, transliterate

def normalize(query):
    if detect_script(query) == "latin":
        return transliterate(query, direction="cyrillic", wordlist=True)
    return query

normalize("dongolok")    # 'дөңгөлөк'
normalize("Дөңгөлөк")    # 'Дөңгөлөк' — уже кириллица, не трогаем
```

**Файл построчно** — память не растёт, переводы строк сохраняются:

```python
from kyrgyz_transliteration import to_latin

with open("in.txt", encoding="utf-8") as src, open("out.txt", "w", encoding="utf-8") as dst:
    for line in src:
        dst.write(to_latin(line, "iso9"))
```

**Сравнить схемы на своих данных:**

```python
from kyrgyz_transliteration import list_schemes, to_latin

for scheme in list_schemes():
    print(scheme.name, to_latin("мүмкүнчүлүк", scheme))
```

**Свой словарь из корпуса.** Берём из своих же текстов слова, которые встречаются
хотя бы трижды, — это надёжнее любого готового списка:

```python
import collections
import re

from kyrgyz_transliteration import Wordlist, transliterate

with open("corpus.txt", encoding="utf-8") as handle:
    counts = collections.Counter(re.findall(r"[а-яёңөү]+", handle.read().lower()))

words = Wordlist(word for word, count in counts.items() if count >= 3)
transliterate("dongolokto kochodo", direction="cyrillic", wordlist=words)
# 'дөңгөлөктө көчөдө'
```

## Производительность

Замер на тексте 128 000 символов (Python 3.12, один поток, лучшее из трёх
измерений):

| Операция | Скорость |
|---|---|
| `to_latin` | 1,0–1,3 млн символов/с (зависит от схемы) |
| `to_cyrillic` | ~1,2 млн символов/с |
| `to_cyrillic` со словарём | ~0,56 млн символов/с |
| сборка встроенного словаря (280 слов, 983 ключа) | ~8 мс, один раз за процесс |

Таблицы схем и встроенный словарь строятся лениво и кешируются, так что первый
вызов чуть дороже остальных. Отдельные буквы и короткие строки транслитерировать
по одной невыгодно: накладные расходы на вызов заметнее самой работы — отдавайте
движку строку целиком.

## Что не восстанавливается обратно

Обратная транслитерация — не магия: `iso9` посимвольная и точная, `turkic` и
`bgn` восстанавливают тексты на кыргызском (проверено на наборе слов в тестах),
но там, где две кириллические буквы пишутся одной латинской, остаются
неизбежные ошибки:

- `е` и `э`: начальная `e` читается как `э` (кыргызская орфография), поэтому
  русские заимствования вроде «Европа» вернутся как «Эвропа»;
- `ң` и `н + г` в `bgn`/`ascii` обе дают `ng`: «конгресс» → `kongress` → «коңресс»;
- `ъ` и `ь` в `turkic`/`ascii` не пишутся и не восстанавливаются;
- `ө`/`о` и `ү`/`у` в `ascii` — по определению схемы.

Если текст должен вернуться байт в байт, используйте `iso9`. Если на входе
латиница без диакритики — словарь (`wordlist=True`).

## Совместимость

- Python 3.9+, стандартная библиотека, ни одной внешней зависимости.
- Типы аннотированы, пакет помечен `py.typed` — mypy и IDE видят подписи.
- Работает с любым текстом: цифры, пунктуация, разметка, переводы строк и чужие
  алфавиты проходят насквозь, длина неалфавитных фрагментов не меняется.
- Специальных блокировок для потоков нет, но и общего изменяемого состояния тоже:
  таблицы схем и встроенный словарь строятся лениво и идемпотентно, так что
  худшее, что может случиться в гонке, — двойная сборка одного и того же кеша.
  Исключение — `register_scheme()` и `Wordlist.add()`: их вызывайте при старте
  приложения, а не из рабочих потоков.

## Тестирование

Окружение (в Ubuntu и Debian системный `pip` защищён PEP 668, поэтому venv):

```bash
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
```

Запуск — все настройки уже в `pyproject.toml`, пути указывать не нужно:

```bash
.venv/bin/python -m pytest              # 140 тестов, ~0,1 с
.venv/bin/python -m pytest -q           # коротко
.venv/bin/python -m pytest -k restore   # только словарь
.venv/bin/python -m pytest tests/test_engine.py -v   # один файл, с именами тестов
.venv/bin/python -m pytest --doctest-modules src -q  # только примеры из документации
.venv/bin/python -m pytest -x --ff      # стоп на первой ошибке, упавшие — первыми
```

Что покрыто:

| Файл | Что проверяет |
|---|---|
| `tests/test_schemes.py` | все 36 букв есть в каждой схеме, `iso9` взаимно однозначна, реестр схем и ошибки |
| `tests/test_engine.py` | движок: контекстные маркеры, запрет правил, меняющих длину, приоритет начала слова |
| `tests/test_transliterate.py` | регистр, диграфы, правила `y`/`ts`/начальной `e`, слаги, круг «кириллица → латиница → кириллица» на корпусе из ~95 слов |
| `tests/test_restore.py` | словарь: ключи всех вариантов набора, неоднозначность, гармония гласных в суффиксах |
| `tests/test_cli.py` | CLI: аргументы, stdin, `--slug`, `--detect`, `--list`, `--table`, `-w`/`--wordlist`, коды возврата |

Примеры из docstring'ов тоже тесты: `testpaths` включает `src`, а `addopts` —
`--doctest-modules`, поэтому код в документации не может разойтись с поведением.

Нашли слово, которое разбирается неверно, — тест пишется в одну строку:

```python
@pytest.mark.parametrize("word", ["көпөлөк", "сүйлөшүү"])
def test_my_words_round_trip(word):
    assert to_cyrillic(to_latin(word), "turkic") == word
```

В PyCharm: Settings → Project → Python Interpreter → Add → Existing → `.venv/bin/python`.
Пакет установлен в editable-режиме, поэтому `import kyrgyz_transliteration`
работает без правки `sys.path`, а тесты запускаются правым щёлчком по `tests/`.

## Как помочь

- **Пополнить словарь.** Частотные кыргызские слова с `ө`, `ү`, `ң` —
  `src/kyrgyz_transliteration/data/kyrgyz_frequent.txt`, одно слово в строке.
  Слова без этих букв тоже полезны: они подтверждают, что диакритики в слове нет,
  и гасят ложные срабатывания по основе. Проверьте, что новое слово не создаёт
  неоднозначный ключ: `builtin_wordlist().ambiguous_keys()`.
- **Добавить схему.** Достаточно таблицы букв — см. [Свои схемы](#свои-схемы).
  В `tests/test_schemes.py` схема автоматически проверяется на полноту алфавита.
- **Прислать слово, которое разбирается неверно.** Это самое ценное: пример
  «набрал X, ожидал Y, получил Z» превращается в тест и правило.
