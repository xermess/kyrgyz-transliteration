Транслитерация кыргызского языка на Python: кириллица ⇄ **английская латиница**.
Только буквы `a-z` — ни турецкого алфавита (`ı ş ç ğ ñ`), ни научного
(`ž ô ù ņ â`). Восстановление регистра, восстановление `ө`, `ү` и `ң` по
словарю, слаги для URL и консольная утилита. Без зависимостей, Python 3.9+.

```python
from kyrgyz_transliteration import to_latin, to_cyrillic, slugify

to_latin("дөңгөлөк")                 # 'dongolok'
to_cyrillic("dongolok")              # 'дөңгөлөк'
to_latin("Кыргыз Республикасы")      # 'Kyrgyz Respublikasy'
to_cyrillic("Kyrgyz Respublikasy")   # 'Кыргыз Республикасы'
slugify("Ысык-Көл облусу")           # 'ysyk-kol-oblusu'
```

## Главная сложность: ө, ү и ң

В английском алфавите этих букв нет. Кыргызы пишут их латиницей так же, как
`о`, `у` и `н`:

| Кириллица | по-английски |
|---|---|
| дөңгөлөк | `dongolok` |
| донголок | `dongolok` |
| өмүр | `omur` |
| түшүнүк | `tushunuk` |

В одну сторону всё однозначно, обратно — нет: и «дөңгөлөк», и «донголок»
подчиняются гармонии гласных, правилами их не различить. Поэтому обратное
направление идёт через **список кыргызских слов, и он включён по умолчанию**:

```python
to_cyrillic("dongolok")                  # 'дөңгөлөк'  — по словарю
to_cyrillic("dongolok", wordlist=False)  # 'донголок'  — только правилами
```

Слово целиком в словаре искать необязательно: окончание отделяется, к нему
применяется гармония гласных, а конечный согласный основы озвончается
(`к → г`, `п → б`), как этого требует кыргызская морфология:

```python
to_cyrillic("dongolokton")   # 'дөңгөлөктөн'
to_cyrillic("dongologu")     # 'дөңгөлөгү'   (к -> г перед гласной)
to_cyrillic("kitebi")        # 'китеби'      (п -> б перед гласной)
to_cyrillic("okmottun")      # 'өкмөттүн'
```

Составные слова ищутся целиком — по частям «Ысык-Көл» от «ысык кол» не отличить:

```python
to_cyrillic("Ysyk-Kol")      # 'Ысык-Көл'
to_cyrillic("Ysyk-Koldon")   # 'Ысык-Көлдөн'
to_cyrillic("uy-bulo")       # 'үй-бүлө'
```

Если различать `ө`/`о`, `ү`/`у` и `ң`/`н` нужно без словаря — берите схему
[`bgn`](#схемы): она пишет их отдельными знаками (`ö`, `ü`, `ng`) и читается
обратно одними правилами.

## Схемы

| Схема | Назначение | Обратимость |
|---|---|---|
| `english` (по умолчанию) | английская латиница: только `a-z`, `ң → n`, `ө → o`, `ү → u`, `ж → j`, `х → kh` | с потерями: `о`/`ө`, `у`/`ү`, `н`/`ң`, `е`/`э`, `й`/`ы` — восстанавливаются по [словарю](#словарь) |

```python
from kyrgyz_transliteration import list_schemes

for scheme in list_schemes():
    print(scheme.name, "-", scheme.title, "(с потерями)" if scheme.lossy else "")
```

### Какую схему выбрать

- **`english`** — почти всегда. Так кыргызы пишут латиницей в жизни: в URL,
  логинах, именах файлов, SMS и мессенджерах. Результат читается по-английски и
  состоит только из `a-z`, а `ө`, `ү` и `ң` возвращаются из словаря.
- **`bgn`** — когда `ө`, `ү` и `ң` должны сохраниться в самой записи: топонимы
  на картах, имена в паспортах, библиографические ссылки, обмен данными. Цена —
  три буквы вне английского алфавита (`ö`, `ü`) и знаки `ʺ`, `ʼ`.

Один и тот же текст в обеих схемах:

| Кириллица | english | bgn |
|---|---|---|
| Ысык-Көл | `Ysyk-Kol` | `Ysyk-Köl` |
| жаңылык | `janylyk` | `jangylyk` |
| мүмкүнчүлүк | `mumkunchuluk` | `mümkünchülük` |
| Чүй облусу | `Chuy oblusu` | `Chüy oblusu` |
| Өкмөт | `Okmot` | `Ökmöt` |
| айтса | `aytsa` | `aytsa` |

Читает библиотека шире, чем пишет: `to_cyrillic()` в любой схеме понимает и
`ö`/`ü` из `bgn`, и апострофы вместо `ъ`/`ь`, так что перемешанный текст
разбирается без настройки.

## API

### `to_latin(text, scheme="english")`

Кириллица → латиница. Регистр сохраняется, включая многобуквенные замены и
аббревиатуры: `Ёлка → Yolka`, `ЁЛКА → YOLKA`. Всё, что не буква (цифры,
пунктуация, разметка, переводы строк), проходит насквозь.

```python
to_latin("Ош шаары")               # 'Osh shaary'
to_latin("КЫРГЫЗ ЭЛИ")             # 'KYRGYZ ELI'
to_latin("Бишкек, 2026-жыл")       # 'Bishkek, 2026-jyl'
to_latin("Жаңыл", "bgn")           # 'Jangyl'
```

### `to_cyrillic(text, scheme="english", wordlist=None)`

Латиница → кириллица. Диграфы имеют приоритет над отдельными буквами
(`shch → щ`, `yo → ё`), а неоднозначные буквы разбираются по контексту:

```python
to_cyrillic("Ysyk-Kol")            # 'Ысык-Көл'  (y после согласной — ы)
to_cyrillic("oy-toy")              # 'ой-той'    (y между гласной и согласной — й)
to_cyrillic("biyik")               # 'бийик'     (y перед узкой гласной — й)
to_cyrillic("aytsa")               # 'айтса'     (ts после гласной — т + с)
to_cyrillic("kontsert")            # 'концерт'   (в остальных случаях — ц)
to_cyrillic("emgek")               # 'эмгек'     (e в начале слова — э)
```

Параметр `wordlist` решает, чем восстанавливать `ө`, `ү` и `ң`:

| Значение | Что делает |
|---|---|
| `None` (по умолчанию) или `True` | встроенный список частотных кыргызских слов |
| `False` | ничего, только правила схемы |
| свой `Wordlist` | ваш список слов — см. [Словарь](#словарь) |

### `transliterate(text, scheme="english", direction="auto", wordlist=None)`

Направление по преобладающей письменности: `"auto"`, `"latin"` или `"cyrillic"`.

```python
transliterate("Бишкек")            # 'Bishkek'
transliterate("Bishkek")           # 'Бишкек'
transliterate("dongolok")          # 'дөңгөлөк'
```

### `slugify(text, separator="-", scheme="english")`

ASCII-слаг для URL, имён файлов и идентификаторов: только `a-z`, `0-9` и
разделитель.

```python
slugify("Ысык-Көл облусу")             # 'ysyk-kol-oblusu'
slugify("Жалал-Абад", separator="_")   # 'jalal_abad'
```

### `detect_script(text)`

`"cyrillic"`, `"latin"`, `"mixed"` или `"unknown"`.

### Прочее

- `alphabet_table(scheme)` — список пар `(кириллица, латиница)` для всех 36 букв.
- `Wordlist`, `builtin_wordlist()`, `restore_words()`, `ascii_key()` — словарь
  для восстановления `ө`, `ү` и `ң`.
- `get_scheme(name)`, `list_schemes()`, `SCHEMES` — доступ к схемам;
  `UnknownSchemeError` — неизвестное имя.
- `Scheme`, `Table`, `apply_table`, `match_case` — собственные схемы и движок.
- `CYRILLIC_LETTERS` — кыргызский алфавит строкой.

## Словарь

Встроенный список — 400+ частотных кыргызских слов. Как он работает:

1. слово ищется по «сплющенному» ASCII-ключу — учитываются все варианты набора:
   `ө`/`ү` как `o`/`u` (или `oe`/`ue`), `ң` как `n` или `ng`, `ж` как `j` или
   `zh`, `ы` и `й` как `y` или `i`, `х` как `h` или `kh`;
2. составное слово (через дефис) сначала ищется целиком, потом по частям;
3. если точного совпадения нет — ищется самая длинная основа (минимум 4 символа,
   считая и озвончённую форму: `дөңгөлөк` → `дөңгөлөг`), а к окончанию
   применяется гармония гласных: `dongolokton → дөңгөлөктөн`, `dongologu →
   дөңгөлөгү`;
4. если слово не нашлось, оно разбирается обычными правилами схемы. То есть
   словарь ничего не портит: без него было бы то же самое.

### Спорные слова

Некоторые пары по-английски пишутся одинаково: `uy` — это и «уй», и «үй»,
`kol` — и «кол», и «көл». По умолчанию такой ключ не используется вовсе, и
слово достаётся правилам. Если одно из слов заметно частотнее, его помечают
**предпочтительным** — звёздочкой в файле списка или `preferred=True` в коде:

```text
уй
*үй        # uy -> үй: дом встречается несравнимо чаще коровы
```

```python
words = Wordlist(["уй"]).add(["үй"], preferred=True)
words.lookup("uy")          # 'үй'
words.ambiguous_keys()      # [] — спор решён
```

Во встроенном списке так помечены `үй`, `кол`, `он`, `тоо` и `кийин`.
Оставшиеся спорные ключи всегда видны: `builtin_wordlist().ambiguous_keys()`.

### Свой список слов

Одно слово в строке, кириллицей, `#` — комментарий, `*` — предпочтительное
чтение:

```python
from kyrgyz_transliteration import Wordlist, builtin_wordlist, to_cyrillic

words = Wordlist.from_file("kyrgyz.txt")               # только свои слова
words = builtin_wordlist().copy().add(["көпөлөк"])      # встроенные + свои

to_cyrillic("kopolokton", wordlist=words)   # 'көпөлөктөн'
```

Чем полнее список, тем лучше результат: встроенный набор — это стартовая точка,
а не полный словарь кыргызского языка.

Справочник `Wordlist`:

| Что | Зачем |
|---|---|
| `Wordlist(words, min_stem=4)` | собрать словарь из слов (кириллицей); `min_stem` — минимальная длина основы при поиске по началу слова |
| `Wordlist.from_file(path)` / `.from_text(text)` | прочитать список: одно слово в строке, `#` — комментарий, `*` — предпочтительное чтение |
| `.add(words, preferred=False)` | дописать слова; возвращает сам словарь, так что вызовы можно цеплять |
| `.copy()` | независимая копия вместе с предпочтительными словами |
| `.merge(other)` | добавить чужой словарь, не потеряв его пометки |
| `.lookup(typed)` | слово по набранной латинице или `None`, если его нет либо ключ спорный |
| `.lookup_stem(key)` | `(основа, длина ключа основы)` — самая длинная однозначная основа |
| `.ambiguous_keys()`, `.preferred()` | спорные ключи и слова, за которыми они закреплены |
| `.words()`, `len(...)`, `"dongolok" in ...` | содержимое словаря |
| `builtin_wordlist()` | встроенный список (кешируется; не меняйте его на месте — делайте `.copy()`) |
| `restore_words(text, wordlist)` | только восстановление слов, без транслитерации |
| `ascii_key(word)` | ключ слова: нижний регистр без диакритики (`dönggölök` → `donggolok`) |

## Свои схемы

Схема — это таблица «кириллица → латиница» плюс необязательные уточнения.
Обратная таблица строится автоматически.

```python
from kyrgyz_transliteration import SCHEMES, Scheme, register_scheme, to_latin

register_scheme(
    Scheme(
        name="passport",
        title="Как в моих документах",
        mapping=dict(SCHEMES["english"].mapping, ж="zh", ө="oe", ү="ue", ң="ng"),
        reverse_word_initial={"e": "э"},
    )
)

to_latin("Жаңыл", "passport")   # 'Zhangyl'
```

Полезные поля `Scheme`:

- `word_initial` — замены только в начале слова;
- `reverse_mapping`, `reverse_word_initial` — правки обратной таблицы;
- `latin_upper` / `latin_lower` — регистровые исключения латиницы;
- `forward_contextual` / `reverse_contextual` — контекстные правила
  `(регулярка, маркер)`; правило помечает неоднозначный символ маркером, а
  маркер переводится через `reverse_mapping`. Замена обязана быть той же длины,
  что и совпадение, поэтому контекст задаётся через `(?<=...)` и `(?=...)`.

## Командная строка

```bash
$ kyrgyz-translit "Кыргыз Республикасы"
Kyrgyz Respublikasy

$ kyrgyz-translit "дөңгөлөк"
dongolok

$ kyrgyz-translit "dongolok"
дөңгөлөк

$ kyrgyz-translit --no-words "dongolok"     # без словаря, одними правилами
донголок

$ kyrgyz-translit -s bgn "Ысык-Көл"
Ysyk-Köl

$ kyrgyz-translit -d cyrillic -s bgn "Ysyk-Köl"
Ысык-Көл

$ kyrgyz-translit --slug "Жалал-Абад облусу"
jalal-abad-oblusu

$ cat text.txt | kyrgyz-translit > text-latin.txt

$ kyrgyz-translit --wordlist kyrgyz.txt "koygoydon"
көйгөйдөн

$ kyrgyz-translit --list          # схемы с описаниями
$ kyrgyz-translit --table bgn     # таблица соответствий
$ kyrgyz-translit --detect "Bishkek"
latin
```

Словарь включён по умолчанию; `--no-words` его отключает, `--wordlist FILE`
добавляет свой список к встроенному (а вместе с `--no-words` — заменяет его).
То же самое доступно как `python -m kyrgyz_transliteration`.

## Как это работает

Один проход по тексту, никаких зависимостей и никакой магии.

1. **Подготовка таблицы.** Схема хранит таблицу «кириллица → латиница»; обратная
   таблица строится из неё автоматически при первом обращении и кешируется.
   Пустые замены (`ъ`, `ь`) в обратную таблицу не попадают, а при конфликте
   побеждает буква, объявленная раньше.
2. **Словарь** (в направлении «латиница → кириллица») работает до всего
   остального: найденные слова сразу заменяются кириллическими, остальное
   достаётся правилам.
3. **Контекстные правила.** До основного прохода по тексту проходят регулярки,
   которые помечают неоднозначные символы служебными маркерами: `y` между
   гласной и согласной → маркер «й», `t` перед `s` после гласной → маркер «т».
   Маркер обязан быть той же длины, что и совпадение, — иначе движок поднимает
   `ValueError`, — поэтому контекст задаётся только через `(?<=...)` и `(?=...)`,
   а нумерация символов остаётся прежней.
4. **Жадное сопоставление.** Для каждой позиции берётся самая длинная
   подходящая последовательность (`shch` раньше `sh`, `sh` раньше `s`), в начале
   слова сначала проверяется таблица `word_initial`. Что не нашлось — цифры,
   пунктуация, разметка, чужие алфавиты — копируется как есть.
5. **Регистр.** Он берётся из исходного фрагмента, а не из замены: слово целиком
   в верхнем регистре даёт `ЁЛКА → YOLKA`, с заглавной — `Ёлка → Yolka`, а у
   составных слов регистр считается по частям: `YSYK-KOL → ЫСЫК-КӨЛ`,
   `Ysyk-Kol → Ысык-Көл`.

Точки расширения — `Scheme` (своя схема), `Table` + `apply_table` (свой движок
на готовой таблице), `match_case` (восстановление регистра отдельно).

## Рецепты

**Слаг для URL.**

```python
from kyrgyz_transliteration import slugify

slugify("Ысык-Көл облусунун жаңылыктары")   # 'ysyk-kol-oblusunun-janylyktary'
```

**Поиск, которому всё равно, чем набран запрос.** Приводим запрос к кириллице и
ищем по одному индексу:

```python
from kyrgyz_transliteration import detect_script, transliterate

def normalize(query):
    if detect_script(query) == "latin":
        return transliterate(query, direction="cyrillic")
    return query

normalize("dongolok")    # 'дөңгөлөк'
normalize("Дөңгөлөк")    # 'Дөңгөлөк' — уже кириллица, не трогаем
```

**Файл построчно** — память не растёт, переводы строк сохраняются:

```python
from kyrgyz_transliteration import to_latin

with open("in.txt", encoding="utf-8") as src, open("out.txt", "w", encoding="utf-8") as dst:
    for line in src:
        dst.write(to_latin(line))
```

**Свой словарь из корпуса.** Берём из своих же текстов слова, которые встречаются
хотя бы трижды, — это надёжнее любого готового списка:

```python
import collections
import re

from kyrgyz_transliteration import Wordlist, builtin_wordlist, transliterate

with open("corpus.txt", encoding="utf-8") as handle:
    counts = collections.Counter(re.findall(r"[а-яёңөү-]+", handle.read().lower()))

words = builtin_wordlist().copy()
words.add(word for word, count in counts.items() if count >= 3)
transliterate("dongolokto kochodo", direction="cyrillic", wordlist=words)
# 'дөңгөлөктө көчөдө'
```

## Производительность

Замер на тексте 128 000 символов (Python 3.14, один поток, лучшее из трёх
измерений):

| Операция | Скорость |
|---|---|
| `to_latin` | ~2,9 млн символов/с |
| `to_cyrillic` без словаря | ~2,1 млн символов/с |
| `to_cyrillic` со словарём (по умолчанию) | ~0,95 млн символов/с |
| сборка встроенного словаря (416 слов, 1543 ключа) | ~0,6 мс, один раз за процесс |

Таблицы схем и встроенный словарь строятся лениво и кешируются, так что первый
вызов чуть дороже остальных. Отдельные буквы и короткие строки транслитерировать
по одной невыгодно: накладные расходы на вызов заметнее самой работы — отдавайте
движку строку целиком. Если `ө`, `ү` и `ң` восстанавливать не нужно,
`wordlist=False` ускоряет обратное направление вдвое.

## Что не восстанавливается обратно

Обратная транслитерация — не магия. Со словарём круг «кириллица → английская
латиница → кириллица» точен на всём встроенном списке, кроме пяти слов, но
неизбежные потери есть:

- **истинные омографы.** `уй`/`үй`, `кол`/`көл`, `он`/`оң`, `тоо`/`төө`,
  `туз`/`түз` по-английски пишутся одинаково. Одно слово пары выигрывает (см.
  [Спорные слова](#спорные-слова)), другое теряется — без контекста выбрать
  нельзя;
- **слова вне словаря.** `ө`, `ү` и `ң` в них не восстановятся: `kopolok`
  вернётся как «кополок», пока «көпөлөк» не попадёт в список;
- **`е` и `э`:** начальная `e` читается как `э` (кыргызская орфография), поэтому
  русские заимствования вроде «Европа» вернутся как «Эвропа»;
- **`ъ` и `ь`** в схеме `english` не пишутся и не восстанавливаются (в `bgn`
  пишутся: `ʺ` и `ʼ`);
- **`ң` и `н + г`** в `bgn` обе дают `ng`: «конгресс» → `kongress` → «коңресс».
  В `english` этой проблемы нет: `ң → n`, и `ng` читается как «нг».

Если `ө`, `ү` и `ң` должны сохраниться в самой записи, берите `bgn`: там круг
точен без всякого словаря.

## Совместимость

- Python 3.9+, стандартная библиотека, ни одной внешней зависимости.
- Типы аннотированы, пакет помечен `py.typed` — mypy и IDE видят подписи.
- Работает с любым текстом: цифры, пунктуация, разметка, переводы строк и чужие
  алфавиты проходят насквозь, длина неалфавитных фрагментов не меняется.
- Специальных блокировок для потоков нет, но и общего изменяемого состояния тоже:
  таблицы схем и встроенный словарь строятся лениво и идемпотентно, так что
  худшее, что может случиться в гонке, — двойная сборка одного и того же кеша.
  Исключение — `register_scheme()` и `Wordlist.add()`: их вызывайте при старте
  приложения, а не из рабочих потоков.

## Тестирование

Окружение (в Ubuntu и Debian системный `pip` защищён PEP 668, поэтому venv):

```bash
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
```

Запуск — все настройки уже в `pyproject.toml`, пути указывать не нужно:

```bash
.venv/bin/python -m pytest              # 162 теста, ~0,1 с
.venv/bin/python -m pytest -q           # коротко
.venv/bin/python -m pytest -k restore   # только словарь
.venv/bin/python -m pytest tests/test_engine.py -v   # один файл, с именами тестов
.venv/bin/python -m pytest --doctest-modules src -q  # только примеры из документации
.venv/bin/python -m pytest -x --ff      # стоп на первой ошибке, упавшие — первыми
```

Что покрыто:

| Файл | Что проверяет |
|---|---|
| `tests/test_schemes.py` | все 36 букв есть в каждой схеме, английский алфавит и ничего кроме, реестр схем и ошибки |
| `tests/test_engine.py` | движок: контекстные маркеры, запрет правил, меняющих длину, приоритет начала слова |
| `tests/test_transliterate.py` | регистр, диграфы, правила `y`/`ts`/начальной `e`, слаги, круг «кириллица → латиница → кириллица» на корпусе из ~75 слов и на всём встроенном словаре |
| `tests/test_restore.py` | словарь: ключи всех вариантов набора, спорные ключи и предпочтения, составные слова, озвончение основы, гармония гласных в окончаниях |
| `tests/test_cli.py` | CLI: аргументы, stdin, `--slug`, `--detect`, `--list`, `--table`, `--no-words`/`--wordlist`, коды возврата |

Примеры из docstring'ов тоже тесты: `testpaths` включает `src`, а `addopts` —
`--doctest-modules`, поэтому код в документации не может разойтись с поведением.

Нашли слово, которое разбирается неверно, — тест пишется в одну строку:

```python
@pytest.mark.parametrize("word", ["көпөлөк", "сүйлөшүү"])
def test_my_words_round_trip(word):
    assert to_cyrillic(to_latin(word)) == word
```

В PyCharm: Settings → Project → Python Interpreter → Add → Existing → `.venv/bin/python`.
Пакет установлен в editable-режиме, поэтому `import kyrgyz_transliteration`
работает без правки `sys.path`, а тесты запускаются правым щёлчком по `tests/`.

## Как помочь

- **Пополнить словарь.** Частотные кыргызские слова с `ө`, `ү`, `ң` —
  `src/kyrgyz_transliteration/data/kyrgyz_frequent.txt`, одно слово в строке.
  Слова без этих букв тоже полезны: они подтверждают, что этих букв в слове нет,
  и гасят ложные срабатывания по основе. Проверьте, что новое слово не создаёт
  спорный ключ: `builtin_wordlist().ambiguous_keys()`; если создаёт — пометьте
  более частотное слово звёздочкой.
- **Добавить схему.** Достаточно таблицы букв — см. [Свои схемы](#свои-схемы).
  В `tests/test_schemes.py` схема автоматически проверяется на полноту алфавита.
- **Прислать слово, которое разбирается неверно.** Это самое ценное: пример
  «набрал X, ожидал Y, получил Z» превращается в тест и правило.
